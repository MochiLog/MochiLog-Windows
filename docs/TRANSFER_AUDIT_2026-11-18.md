# 転送調査（2026-11-18）

Windows実機のネイティブ診断JSONと既存日次ログをSCPで取得した。PowerShellによるログの再集計・深いJSON変換は使わない。
単一スナップショットのprivateBytesは約238MiB、managedBytesは約17MiB。
累積割当量約6GBは現在保持中のメモリではなく、この値だけでリークとは認定しない。

## Mac側との照合

Macに接続開始から25秒の絶対切断が残っていたが、Windowsは応答準備後に要求期限を解除し、64KiBの各書き込み後に無進捗期限を更新する実装である。
低速転送・停止・サーバー終了取消の試験は引き続き成功。Macの等価パス表記によるWatchトークン失敗は、Windowsの相対パストークン生成では再現していない。

両側で失敗を追えるよう、Windowsの例外履歴に要求受信・ペアリング・解除・応答準備・書き込みの段階と例外型/HResultを追加した。
取消はサーバー終了か期限切れかを区別する。要求本文や鍵は記録しない。
不正JSONが接続を閉じ、要求段階と例外コードを診断に残す回帰試験を追加した。

## 検証

実機上の一時ディレクトリで、`MOCHILOG_PROTOCOL_TEST`のランダムな保存先を使用。
通常アプリのペアリング・キュー・記録やAppleドライバーは変更していない。

`dotnet run --project tests/ProtocolTests -c Release`が成功した。
暗号化ペアリング、署名付き要求、受信確認、再送・降格拒否、本体/Watchの分離、重複事前照会、4端末の同意別共有、保管/再送、診断交換を確認。
診断1000回の書き出し、Job Objectによる子孫停止、無応答・過大出力・取消の制限も成功した。

収集先が一時的に応答しない既存ログだけで、外出中のiPhoneや接続していないiPadの製品不具合とは判断しない。
隔離試験は現在の物理端末から新しい日次ファイルを収集できた証拠ではない。
