# PC連携の失敗状態保持（2026-11-18）

実機の最新ネイティブ診断では、CollectionStatusに直近の取得失敗が出る一方、デバイスのLastCollectionには以前の成功・完了が残っていた。収集例外の経路で結果を更新していなかったことが原因。

成功・失敗の両方がStateStore.SaveCollectionを使い、端末ごとの結果を同じロックと暗号化・原子的保存で更新するようにした。取得失敗時は失敗1件・未完了を保持する。保存できない状況の追加例外はログに記録し、元の失敗処理を中断させない。アプリ終了による取消は収集失敗と分ける。

実機Windows上の隔離チェックアウトで暗号化プロトコルの全試験とWinUIアプリ全体のReleaseビルドが成功した。新しい回帰試験は、保存・再読込後も失敗端末の古い成功が残らず、別端末の結果・ペアリング鍵・受領記録が保持されることを確認する。本番の状態ファイルやAppleドライバーは変更していない。PowerShellでログを再集計せず、既存の小さな出力ファイルを直接SCPした。

スマホ共通クライアントの[転送回復・権限UIの検証](https://github.com/MochiLog/MochiLog/blob/main/docs/PC_LINK_STABILITY_2026-11-18.md)もWindowsへの接続に適用する。iOS/macOSのローカルネットワーク権限とWindowsのファイアウォールは別の仕組みであり、Windowsの待受ポートが開いたことだけでファイアウォール許可済みとは表示しない。

5分の収集周期、当日分完了後の休止、ペアリング形式、暗号化プロトコルは維持している。外出・ロック・古いIPでの失敗だけをアプリ不具合として扱わず、帰宅後の収集再開を遅らせる新しい待機時間は追加していない。
